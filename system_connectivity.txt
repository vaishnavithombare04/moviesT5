================================================================================
MOVIE MANAGEMENT SYSTEM - FULL-STACK CONNECTIVITY & ARCHITECTURE GUIDE
================================================================================

This document explains in detail how the Frontend (React), Backend (Node.js/Express),
and Database (MySQL) communicate and work together.

--------------------------------------------------------------------------------
1. HIGH-LEVEL SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------

  +-------------------------------------------------------------+
  |                   FRONTEND (React + CSS)                    |
  |                  Runs on: http://localhost:3000             |
  +-------------------------------------------------------------+
                                │   ▲
                                │   │  HTTP / REST API (JSON)
           fetch() with JWT in  │   │  CORS Enabled
           Authorization header │   │  Returns { success, data, message }
                                ▼   │
  +-------------------------------------------------------------+
  |               BACKEND (Node.js + Express.js)                |

--------------------------------------------------------------------------------
2. DATABASE LAYER: HOW BACKEND CONNECTS TO MYSQL
--------------------------------------------------------------------------------

* Configuration File: backend/config/db.js
* Library: mysql2/promise

How it works:
1. Instead of opening and closing a single connection for every query, the backend
   creates a Connection Pool (`mysql.createPool`).
2. The pool holds up to 10 reusable connections to the MySQL database:
   - Host: localhost
   - Port: 3306
   - User: root
   - Password: process.env.DB_PASSWORD (loaded securely from backend/.env)
   - Database: movie_management
3. Query Execution:
   Controllers use `pool.query(sql, [params])`.
   Parameterized queries (`?`) ensure that user inputs are safely escaped,
   preventing SQL Injection attacks completely.

--------------------------------------------------------------------------------
3. BACKEND LAYER: HOW EXPRESS EXPOSES AND PROTECTS APIS
--------------------------------------------------------------------------------

* Main File: backend/server.js
* Port: 6500

Key Components:
1. CORS Middleware:
   `app.use(cors())` enables Cross-Origin Resource Sharing. Without this, your
   browser would block React on port 3000 from fetching data from port 6500.

2. Body Parser:
   `app.use(express.json())` parses incoming JSON request bodies into `req.body`.

3. Router Delegation:
   `server.js` mounts modular routes:
   - app.use("/api/auth", authRoutes)     -> Register & Login
   - app.use("/api/genres", genreRoutes)  -> Genre CRUD operations
   - app.use("/api/movies", movieRoutes)  -> Movie CRUD, search, filter, sort

4. JWT Security & Role Authorization (backend/middleware/authMiddleware.js):
   - `verifyToken`: Reads the header `Authorization: Bearer <TOKEN>`, verifies
     the cryptographic signature with `process.env.JWT_SECRET`, and attaches the
     decoded payload (`req.user = { id, email, role }`) to the request.
   - `verifyAdmin`: Checks `req.user.role === 'admin'`. If a normal user tries to
     access an admin route, Express rejects the request with HTTP 403 Forbidden.

--------------------------------------------------------------------------------
4. FRONTEND LAYER: HOW REACT TALKS TO THE BACKEND
--------------------------------------------------------------------------------

* Main File: frontend/src/services/api.js
* Base URL: http://localhost:6500/api

Key Components:
1. The Centralized API Client (`apiRequest`):
   Every frontend request passes through a single helper:
   ```javascript
   export const apiRequest = async (endpoint, options = {}) => {
     const token = localStorage.getItem("token"); // Retrieve saved JWT
     const headers = { "Content-Type": "application/json", ...options.headers };

     if (token) {
       headers["Authorization"] = `Bearer ${token}`; // Auto-attach token
     }

     const response = await fetch(`${BASE_URL}${endpoint}`, { ...options, headers });
     const data = await response.json();
     if (!response.ok) throw new Error(data.message);
     return data;
   };
   ```

2. Authentication Context (`frontend/src/context/AuthContext.jsx`):
   - Stores `user`, `token`, and `isAdmin` in React memory (`useState`).
   - Persists credentials in browser `localStorage`.
   - On page refresh, it checks `localStorage` and restores the user session
     so the user stays logged in.

3. Route Guards (`frontend/src/components/ProtectedRoute.jsx`):
   - `ProtectedRoute`: If `user === null`, automatically redirects to `/login`.
   - `ProtectedRoute adminOnly={true}`: If `role !== 'admin'`, redirects to `/`.
   - `PublicOnlyRoute`: If already logged in, visiting `/login` or `/register`
     redirects directly to `/`.

5. STEP-BY-STEP END-TO-END DATA FLOW TRACES
--------------------------------------------------------------------------------

TRACE A: USER REGISTRATION
1. User enters Full Name, Email, and Password on http://localhost:3000/register.
2. React triggers `authAPI.register(formData)`.
3. Browser sends HTTP POST to `http://localhost:6500/api/auth/register`.
4. Express receives request -> `authController.registerUser` runs.
5. Controller queries MySQL: `SELECT id FROM users WHERE email = ?`.
6. Password hashed using bcrypt (10 rounds of salt).
7. Controller inserts into MySQL: `INSERT INTO users (full_name, email, password, role) VALUES (?, ?, ?, 'user')`.
8. Express responds with status 201 Created: `{ success: true, message: "Registration successful" }`.
9. React displays green success banner and redirects user to `/login`.

TRACE B: USER / ADMIN LOGIN
1. User enters Email and Password on http://localhost:3000/login.
2. React triggers `authAPI.login(formData)`.
3. Browser sends HTTP POST to `http://localhost:6500/api/auth/login`.
4. Express receives request -> `authController.loginUser` runs.
5. MySQL executes: `SELECT id, full_name, email, password, role FROM users WHERE email = ?`.
6. `bcrypt.compare` checks entered password against database hash.
7. Backend signs JWT token containing: `{ id, email, role }`.
8. Express responds with status 200 OK: `{ success: true, token: "...", user: { ... } }`.
9. React's `AuthContext` saves `token` and `user` to `localStorage`.
10. If Admin: Navbar displays `Admin: <email>` and reveals "Add Movie" / "Add Genre".
    If Normal User: Navbar displays `<email>` and "Log out".
11. React navigates to `/` (Home Movie Catalog).

TRACE C: BROWSING & FILTERING MOVIES (HOME CATALOG)
1. User visits http://localhost:3000/ (protected by login).
2. React's `HomePage.jsx` triggers two requests:
   - `genreAPI.getAll()` -> `GET /api/genres` -> Populates sidebar category list.
   - `movieAPI.getAll({ search, genre_id, page })` -> `GET /api/movies` -> Populates card grid.
3. Express queries MySQL with a JOIN:
   `SELECT m.*, g.name AS genre_name FROM movies m LEFT JOIN genres g ON m.genre_id = g.id WHERE ... ORDER BY ... LIMIT ... OFFSET ...`
4. MySQL returns the rows.
5. Express sends JSON array of movies back to React.
6. React renders the movies as 3D flipping cards.
7. User clicks a card -> Card rotates 180 degrees in CSS to reveal description.
8. User clicks "Watch Trailer ▶" -> Event propagation is stopped (`e.stopPropagation()`)
   and YouTube opens in a new tab.

TRACE D: ADMIN ADDING A NEW MOVIE
1. Admin visits http://localhost:3000/movies/new.
2. Form pre-loads genres from MySQL via `GET /api/genres`.
3. Admin fills out Title, Genre, Rating, Duration, Poster URL, Trailer URL, Synopsis.
4. React calls `movieAPI.create(movieData)`.
5. Browser sends HTTP POST to `http://localhost:6500/api/movies` with header:
   `Authorization: Bearer <ADMIN_JWT_TOKEN>`.
6. Express runs `verifyToken` (validates token) -> runs `verifyAdmin` (confirms role === 'admin').
7. MySQL executes:
   `INSERT INTO movies (title, genre_id, rating, duration, poster_url, trailer_url, description, release_year) VALUES (?, ?, ?, ?, ?, ?, ?, ?)`.
8. Express responds with 201 Created.
9. React shows green success notification and redirects to `/`, where the new
   movie card immediately appears.

TRACE E: ADMIN UPDATING A MOVIE
1. Admin clicks "✏️ Edit" on any card on the Home Page.
2. React opens the Edit Movie Modal pre-populated with existing movie values.
3. Admin edits data and clicks "Save Changes".
4. React calls `movieAPI.update(id, formData)`.
5. Browser sends HTTP PUT to `http://localhost:6500/api/movies/:id` with Bearer token.
6. Express verifies admin privileges, then runs MySQL UPDATE query.
7. Express responds with 200 OK.
8. React closes the modal and re-renders the updated card in real-time.

TRACE F: ADMIN DELETING A MOVIE
1. Admin clicks "🗑️ Delete" on any movie card.
2. Browser displays confirmation dialog (`window.confirm`).
3. Admin confirms -> React calls `movieAPI.delete(id)`.
4. Browser sends HTTP DELETE to `http://localhost:6500/api/movies/:id` with Bearer token.
5. Express verifies admin privileges -> MySQL executes `DELETE FROM movies WHERE id = ?`.
6. Express responds with 200 OK.
7. React removes the movie from the screen and shows a success alert.

7. MODULES & PACKAGES USED IN THE PROJECT (AND WHY THEY ARE USED)
================================================================================

This section details every external package, module, and library used across the
Backend and Frontend, along with the exact reasons why each was chosen.

--------------------------------------------------------------------------------
A. BACKEND MODULES (Node.js & Express)
--------------------------------------------------------------------------------

1. express (v5.3.0)
   - What it is: A fast, minimalist web application framework for Node.js.
   - Why it is used:
     * Provides the HTTP server engine to listen on port 6500.
     * Simplifies routing (`Router()`) to cleanly separate Auth, Genre, and Movie endpoints.
     * Provides the middleware architecture (`app.use()`) for parsing JSON bodies,
       handling CORS, and verifying JWT authorization tokens.

2. mysql2 (v3.24.6)
   - What it is: A high-performance MySQL driver for Node.js supporting Promises.
   - Why it is used:
     * Enables async/await database operations via `mysql2/promise`.
     * Manages a connection pool (`createPool`) to reuse database connections efficiently
       under load without reconnecting on every query.
     * Enforces parameterized query syntax (`?`) to automatically escape inputs and
       prevent SQL Injection attacks completely.

3. bcrypt (v6.0.0)
   - What it is: An industry-standard cryptographic library for hashing passwords.
   - Why it is used:
     * Never stores plaintext passwords in the database (security compliance).
     * Uses slow one-way hashing with salt rounds (`bcrypt.hash(password, 10)`), making
       hashes resistant to brute-force and rainbow table attacks.
     * Safely verifies user passwords on login using `bcrypt.compare()`.

4. jsonwebtoken (v9.0.3)
   - What it is: An implementation of JSON Web Tokens (JWT) for Node.js.
   - Why it is used:
     * Enables stateless authentication: the server does not need to store user sessions
       in database memory.
     * Issues an encrypted, signed digital token upon login containing user metadata
       (`id`, `email`, and `role`).
     * The `verifyToken` middleware verifies the token signature on protected requests,
       instantly authenticating the caller.

5. cors (v2.8.6)
   - What it is: Express middleware for Cross-Origin Resource Sharing.
   - Why it is used:
     * Modern browsers block web apps running on one origin (`http://localhost:3000`)
       from requesting data from a different origin (`http://localhost:6500`) due to
       Same-Origin Security Policy.
     * `cors()` sets the necessary HTTP response headers (`Access-Control-Allow-Origin: *`)
       so the React frontend can fetch data without browser network blocks.

6. dotenv (v18.0.9)
   - What it is: A zero-dependency module that loads environment variables from a `.env` file.
   - Why it is used:
     * Keeps sensitive credentials (e.g. `DB_PASSWORD`, `JWT_SECRET`, port numbers)
       safely outside the git repository and source code.
     * Automatically injects variables into `process.env`.

7. nodemon (v3.1.14) [Dev Dependency]
   - What it is: A developer tool that monitors code changes in the backend directory.
   - Why it is used:
     * Automatically restarts the Node.js server whenever backend code is saved,
       eliminating the need to manually stop and restart `node server.js` during development.

--------------------------------------------------------------------------------
B. FRONTEND MODULES (React + Vite)
--------------------------------------------------------------------------------

1. react (v18.3.1)
   - What it is: The core declarative JavaScript library for building component-based UIs.
   - Why it is used:
     * Provides virtual DOM rendering for high performance.
     * Manages reactive state and lifecycle with built-in hooks:
       - `useState`: Manages local component state (search query, filter, modal data).
       - `useEffect`: Triggers asynchronous side effects (fetching movies/genres on load).
       - `useContext`: Shares global authentication state across all components without prop drilling.
       - `useCallback`: Optimizes function references to prevent unnecessary re-fetches.
     * Built purely without Redux for clean, maintainable, beginner-friendly code.

2. react-dom (v18.3.1)
   - What it is: The entry point to the DOM and server renderers for React.
   - Why it is used:
     * Mounts the top-level React component tree (`<App />`) into the physical browser
       DOM element (`<div id="root"></div>`) via `ReactDOM.createRoot()`.

3. react-router-dom (v6.28.0)
   - What it is: The official routing library for React web applications.
   - Why it is used:
     * Enables Single Page Application (SPA) navigation without page reloads.
     * Provides `<Routes>`, `<Route>`, `<Navigate>`, `<Link>`, and `<NavLink>`.
     * Powers the `useNavigate()` hook for smooth programmatic redirects (e.g. redirecting
       to the home page after login or movie creation).
     * Enforces route-level access control via `<ProtectedRoute>` and `<PublicOnlyRoute>`.

4. vite (v6.0.1) [Dev Dependency]
   - What it is: A next-generation frontend build tool and development server.
   - Why it is used:
     * Replaces slow legacy bundlers like Webpack / Create React App with near-instant
       server startup and lightning-fast Hot Module Replacement (HMR).
     * Configured to run on port 3000 to match the system's interactive wireframes.
     * Builds and minifies optimized production bundles via Rollup (`npm run build`).

5. @vitejs/plugin-react (v4.3.4) [Dev Dependency]
   - What it is: The official Vite plugin for React applications.
   - Why it is used:
     * Provides JSX/TSX transformation and Babel/SWC integration.
     * Enables React Fast Refresh, preserving component state between code edits.

--------------------------------------------------------------------------------
C. CORE ARCHITECTURAL STANDARDS
--------------------------------------------------------------------------------

1. ES Modules ("type": "module" in package.json):
   - Standardizes modern JavaScript syntax (`import` / `export`) across both frontend
     and backend, ensuring code consistency throughout the entire repository.

2. Pure CSS (No Heavy UI Frameworks or Redux):
   - Built with bespoke CSS matching the exact design specifications in `flowcharts.html`.
   - Avoids Redux or external state manager overhead by leveraging standard React hooks
     (`useState` + `AuthContext`).
